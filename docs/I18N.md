# Language, RTL and locale

## Current state

| Area                     | Status                                                                                                                                                                                                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI language              | English                                                                                                                                                                                                                                                                                              |
| Hebrew **data**          | Fully supported everywhere: names, addresses, notes, part names, search, CSV exports (UTF-8 with BOM, so Excel opens Hebrew correctly)                                                                                                                                                               |
| Customer documents (PDF) | Hebrew text renders correctly (embedded Heebo font, OFL-licensed), with the ₪ sign. Document layout is left-to-right, with Hebrew runs shown in correct reading order. Checked visually on generated PDFs                                                                                            |
| RTL layout readiness     | Layouts use logical CSS properties only (`ms-*`, `pe-*`, `start-*`, `text-start`). A check of all components finds no physical left/right utilities apart from direction-neutral dialog centring. With `<html dir="rtl">` the layout mirrors; see the screenshot in [WALKTHROUGH.md](WALKTHROUGH.md) |
| Centralized strings      | Navigation labels and all status/enum labels live in `src/lib/i18n.ts` (`en` dictionary). Page copy, form labels and messages are still inline English in components                                                                                                                                 |
| Numbers, money, dates    | `Intl` with `APP_LOCALE` (default `en-IL`: ₪, day-month-year) and the business time zone `TZ` (default `Asia/Jerusalem`)                                                                                                                                                                             |

## Path to a full Hebrew UI

1. **Extract strings.** Move inline copy into the dictionary, namespaced by module (`customers.*`,
   `orders.*`, `errors.*`). Zod messages in `src/domain/schemas` become keys resolved at the edge.
   This is the bulk of the work (a few hundred strings).
2. **Add `he`.** Create a `he` dictionary with the same TypeScript shape as `en`, so a missing key is a
   compile error, and have a native speaker review the business terms (הצעת מחיר, הזמנה, תעודת משלוח,
   מקדמה…).
3. **Select per request.** Store the preference on the `User` (or in a cookie). The root layout sets
   `<html lang="he" dir="rtl">`, and the server passes the dictionary to client components.
4. **Mirror icons that imply direction.** Chevrons for back/next and "move up/down" arrows need an
   `rtl:-scale-x-100`.
5. **PDFs.** Add an RTL template variant: right-aligned header, mirrored table column order, and Hebrew
   labels ("הצעת מחיר", "אינה חשבונית מס").
6. **Verify.** Add a Playwright project that runs the responsive and workflow specs with `dir=rtl`, plus
   screenshot review.

Tax documents: even with a Hebrew UI, PrintForge's documents stay non-tax documents. Issuing חשבונית מס /
קבלה requires certified software and is intentionally out of scope.
