# Hands-on walkthrough

I walked through the production build (`npm run build` and then `npm run start:standalone`, the same server Docker
runs), against the **demo database** (`npm run db:seed:demo`), at 1366×900 and on a 375 px phone viewport,
driven by Playwright. No browser console errors or page errors occurred on any screen. All data shown is
fictional demo data.

Problems found during the walkthrough were fixed before these screenshots were taken. They are listed at
the end.

## Problems found and fixed during the walkthrough

| Problem                                                                                                                                                                                                                                                                       | Fix                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Customer PDFs had no footer, so the "not a tax invoice" disclaimer and page numbers were missing.** react-pdf 4 silently drops `fixed` elements that use `render()` when `lineHeight` is set on `<Page>`. The old test only checked the document data, not the rendered PDF | Absolute line heights on a content wrapper. The integration test now extracts the rendered PDF text and asserts the disclaimer, the page footer and the absence of cost/margin/notes. It fails without the fix |
| Quote-line numeric fields were too narrow ("14.6…"), and a wrapping label misaligned the inputs                                                                                                                                                                               | Two-row layout on wide screens                                                                                                                                                                                 |
| Job numbers and grams wrapped in the order's print-jobs table                                                                                                                                                                                                                 | `whitespace-nowrap` on those cells                                                                                                                                                                             |
| "1 days left"                                                                                                                                                                                                                                                                 | Pluralization helper                                                                                                                                                                                           |
| Dashboard said "3 item(s) need attention" above a longer list                                                                                                                                                                                                                 | "3 of 5 alerts need attention"                                                                                                                                                                                 |
| History showed raw codes ("QUEUED → PRINTING")                                                                                                                                                                                                                                | Readable status names in new history entries                                                                                                                                                                   |
| The slicer dialog said "No PLA material matches" when PLA existed in other colours                                                                                                                                                                                            | The hint now distinguishes "no material of this type" from "none in this colour — choose one"                                                                                                                  |

## Also verified outside the browser

- **Docker Compose**, using a sandbox build of the same Dockerfile (the sandbox needed a proxy/CA variant):
  - The stack starts: db healthy, migrations applied, app healthy.
  - First-run setup rejects a wrong `SETUP_TOKEN`. Login works, and so do customer creation and CSV/ZIP export.
  - The CSP and `X-Frame-Options` headers are present, and the session cookie is `HttpOnly`.
  - The backup service writes verified dumps into the host folder.
  - The restore procedure in [BACKUP.md](BACKUP.md) (steps 1–4) brings back deleted data and uploads.
  - Password reset through the `migrate` image works.
- **Backups:** `npm run test:backup` restores all 31 tables with identical row counts.
